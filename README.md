# Sreda Fantasy · первая онлайн-версия

Общий многопользовательский сайт для дружеской фэнтези-лиги. Бюджет 50.0, 1 вратарь + 5 полевых в основе + 2 полевых в запасе, визуальная схема 1–2–2, капитан и вице-капитан, максимум 2 трансфера на тур, дедлайн в 20:30 Europe/Riga, просмотр чужих составов только после дедлайна.

## Что реализовано

- Адаптивный интерфейс для телефона.
- Список игроков и цены **из Supabase**, без копирования игроков в код.
- Регистрация и вход по имени и PIN (6–12 цифр); PIN хранится как salted scrypt с серверным pepper.
- Серверная сессия через `HttpOnly; SameSite=Lax; Secure` cookie на Vercel.
- Ограничение частоты попыток входа и регистрации через таблицу в Supabase.
- Составы, капитан, скамейка, проверка бюджета, дедлайна и 2 трансферов **в базе в одной транзакции**.
- Общая таблица менеджеров, закрытые до дедлайна составы.

## Что ещё НЕ реализовано

**Это функциональная тестовая версия, не полный публичный запуск лиги.** Нет админки ввода статистики, автоматического подсчёта очков, автоматического создания каждого следующего тура, импорта Sreda Eight и полноценного архива старых туров. Отображаемые очки будут нулевыми, пока не внесены результаты. Не приглашайте всех менеджеров до проверки тестовыми пользователями.

## Настройка Supabase

1. Уже созданную схему из восьми таблиц **не удалять**.
2. Игроков (39 штук) **не импортировать повторно** — они уже есть.
3. Откройте Supabase → SQL Editor и запустите `supabase/002_online_features.sql` один раз.
4. Скрипт создаёт `api_rate_limits`, защищённые SQL-функции `consume_rate_limit` и `save_fantasy_roster`, а также первый тур **11 ноября 2026, 20:30 Riga**. Если первую игру нужно провести в другую дату — сначала измените её в конце SQL.
5. Дедлайн хранится как `timestamptz` с часовым поясом Риги и корректным переходом на летнее время для созданного тура.

## Публикация в Vercel

1. Загрузите **все файлы и папки** из этого архива в корень репозитория GitHub `rrruslanapaev-creator/sreda-fantasy`. Папки `api/` и `supabase/` должны сохраниться.
2. Vercel → **Add New → Project** → импорт репозитория.
3. Framework Preset: **Other** (это статический HTML с Node.js API в папке `api`). Build Command — оставить пустым; Output Directory — по умолчанию.
4. Settings → Environment Variables: добавьте три переменные `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `AUTH_PEPPER`. Имена должны совпадать **точно**.
5. `SUPABASE_URL` — URL проекта из Supabase → Project Settings → API.
6. `SUPABASE_SERVICE_ROLE_KEY` — **серверный** secret/service_role ключ Supabase (не `anon`). **Не отправляйте этот ключ в чат, не записывайте его в код, не называйте переменную `NEXT_PUBLIC_...`.**
7. `AUTH_PEPPER` — своя криптографически случайная строка длиной минимум 32 символа, сгенерированная в менеджере паролей. Храните отдельно. После начала регистрации менять её нельзя: существующие PIN перестанут подходить.
8. Deploy и откройте выданный адрес `*.vercel.app`.

### Важно о безопасности

Все таблицы имеют включённый RLS и закрытый доступ для `anon`/`authenticated` по предыдущему SQL. Серверный ключ должен находиться **только в переменных Vercel**, API-функция использует его на сервере. Не размещайте `.env` или переменные доступа на GitHub, даже в приватном репозитории.

Код создан как тестовая версия и **не проходил полное интеграционное тестирование с живым Supabase**, поскольку доступ к секретам не предоставлялся. Сначала проверьте регистрацию, невозможность просмотра чужого состава до дедлайна, ограничение бюджета и трансферов, затем постепенно открывайте доступ участникам.

## Запуск локально

Скопируйте `.env.example` в `.env.local` и задайте реальные локальные секреты. Установите `npm install`. Для запуска Vercel функций и статических файлов используйте `npx vercel dev` после авторизации Vercel CLI.
